# Research quality engine v2

The engine enforces *structural eligibility for expert review*, not mathematical proof of comprehension, novelty or publication acceptance. The companion agent must actually read source texts and construct the reasoning. Code cannot independently authenticate every uploaded document, observer or interpretation.

The original rendering/scoring/search pipeline remains. New native modules: `core/reading.py`, `discovery.py`, `protocol.py`, `gates.py`, `framework.py`, `design.py`, `novelty.py`, `editorial.py`, `deliverables.py` and `pack.py`. Extended `models.py` and `core/graph.py` carry versioned reading/framework/design/novelty/argument inputs. Native renderer adds framework/conditional feasibility and unmistakable provisional status. `render/inspect.py` checks readable type, page content, source presence and link syntax/internal destinations. It explicitly does not claim offline external-link resolution.

G1 checks actual preserved ERIC responses, exact logs and hashed/date-stamped Scholar observations plus original prospective protocol. Cached responses are not new executions. User observations remain declared imports with an integrity artifact, not independently authenticated browser actions. G2 counts independent highly relevant full texts with versioned lawful local artifacts, coverage, checked passages and the required content dimensions. A record saying 'full text' or a resolving DOI is insufficient. Default >=10 is not reduced by a smaller CLI threshold. G3 requires two independent qualified works per major comparative claim and preserves declared opposition; framework/method-fit must pass. G4 challenges novelty against closest content and the strongest rival; country/method-label swaps or an existing answer without a substantive remainder fail. G5 checks actual native CLI/renderer receipt, all 15 matrix groups, linked artifacts, PDF QA, bibliography/source IDs and sealed output digests. `scripts/validate_research_pack.py` independently recomputes the published gate statuses.

All relevant runs write Research_Quality_Gates.json, Full_Text_Reading_Audit.csv/json, Evidence_Matrix.csv/json, Evidence_Ledger.json, Argument_Graph.json, Closest_Study_Novelty_Comparison.csv/json, Theoretical_Conceptual_Framework.json, Framework_Diagram.json, Framework.mmd, Framework.svg, Theory_RQ_Evidence_Method_Alignment.csv, Framework_Audit.json, Study_Design_Audit.json, Editorial_Audit.json, Discovery_Observations.json, Execution_Receipt.json and QA_Report.md. Old matrix/graph/ledger names remain aliases. Full source texts are not bundled. Receipt hashes show modification after a native run; they are not cryptographic attestations of external truth.

The framework is created from source-linked candidate lenses, primary selection or justified synthesis, defined/bounded constructs, relationships and explicit revision triggers. Labels and diagrams distinguish source-verified, hypothesised and sensitising links. RQ/claim/measure/coding/analysis alignment and supplied near-synonym boundaries drive location-specific drift checks. The model can flag missing outcome operationalisation; semantic judgement still needs the agent. Mixed-methods plans require complementary QUAN/QUAL questions and explicit timing/connection/joint display/discordance/meta-inference, with feasible go/no-go conditions, ethics and fallback. Equal sample sizes are never required.

Editorial dimensions use anchored 0–4 evidence-linked judgements. Automatic indications are provisional and capped at partial evidence. Critical source accuracy/novelty/theory-fit/method-fit <=2 block EDITORIALLY_READY_FOR_EXPERT_REVIEW. Synthetic runs never receive production research acceptance even when every structural gate is exercised successfully.

Native PDF format v2 retains the legacy semantic A–F content and uses A–H ordering: focus; gap; argument spine; framework; conditional methods; full matrix; references; verification and gates. It remains A4 monochrome serif, readable multi-line tables and compact cells. No target-word-length essay is generated.

Migration: source records without schema_version load as v1; old access flags remain unpromoted. v2 adds `reading` and has a 20-word quotation default. Existing explicit v1 25-word inputs remain readable but cannot earn substantive v2 acceptance without rights/revision. `audit.passed` is retained solely for v1 layout API compatibility; it is deprecated as a completion signal. Use `layout_passed`, `research_passed` and `research_quality.overall_status`. CLI JSON names these distinctions explicitly. Strict CLI exits 3 after saving provisional outputs; format/input errors use 2; layout errors use 1. `--quality-level exploratory` cannot relax a substantive `full` request.

Metadata matching, exact spans, artifact hashes, observed source provenance and scientific interpretations are different layers. Missing actual Scholar access, full-text work, publisher authenticity, interpretative review or external link checks stay visibly incomplete; the engine does not invent them. No new network model/provider key is required for these validators.
